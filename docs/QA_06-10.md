## Constats

### Critiques
1. **Migrations non appliquées dans Lovable Cloud.** Un fichier `.sql` dans Git n’est pas une base : Lovable n’exécute une
   migration que sur demande et après approbation. Toute inscription créait un compte sans profil ni rôle.
2. **Aucun organisme configuré.** Une fois les migrations appliquées, le trigger d’inscription refuse tout compte tant
   qu’aucun organisme n’existe (« Aucun organisme de formation n’est configuré »). → `supabase/admin_production.sql`.
3. **Consignes Lovable fausses.** `KNOWLEDGE.md` pointait vers `src/domaine`, `src/client/ecrans`, `src/serveur`,
   absents (le code était dans `docs/reference-implementation/`). Le script `preparer-edge-functions.mjs` échouait
   pour la même raison.

### Majeurs
4. Pas de « mot de passe oublié » ni d’adresse de retour après confirmation d’e-mail.
5. Toute connexion Google crée un « formateur candidat » (comportement du trigger sans invitation) : décision à prendre.
6. Lint inexploitable (3 205 problèmes) : les vraies alertes étaient noyées.
7. Aucun contrôle automatique à chaque modification ; un seul test d’interface.

### Mineurs
8. Boutons imbriqués dans des liens sur l’accueil (`<a><button>`, HTML invalide, double arrêt au clavier).
9. Badge « Edit with Lovable » visible ; image de partage Lovable ; pas de domaine personnalisé.
10. 5 écrans sur 19 raccordés (conforme à `roadmap.md`).
